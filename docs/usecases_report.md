## Что это за продукт (на одном экране)

Регионы: центр Сочи (229 отелей Островка, запускается по умолчанию) и Адлер (339 отелей, `REGION=adler`). Апартаменты и жилые квартиры отсеяны.

1. **Данные.**
   - Карточки и отзывы Островка (наш скрап).
   - OpenStreetMap (OSM, открытая карта): здания с этажностью, дороги, железная дорога, пляжи, кафе и так далее.
   - Карта высот Copernicus GLO-30: рельеф, высоты зданий и деревьев.
   - Климат и температура моря по месяцам из Open-Meteo за 2022–2025 годы.
   - Для всех источников есть скрипты загрузки в `scripts/`, а не только готовые файлы.
2. **Инструменты-примитивы, которые считают код, а не LLM:**
   - видно ли море с каждого фасада и с какого этажа;
   - куда садится солнце по месяцам;
   - пешком до пляжа по реальным дорожкам, с подъёмом и переходами через железную дорогу и крупные дороги;
   - шум ночью и днём по сторонам здания;
   - что рядом и открыто ли ночью;
   - поиск по отзывам и карточке с цитатами;
   - климат.
3. **Характеристики.** Каждая описана в YAML-файле в `registry/`: какие инструменты вызвать, как получить значение, какая уверенность, сколько живёт факт и какой вопрос задать отельеру. Сейчас их 18.
4. **Факты.** Каждый факт хранится с источником, методом, уверенностью, датой, сроком годности и уликами: цитатой или расчётом. Если источники спорят, система это видит и называет тип спора, например «отельер против отзывов» или «расчёт против заявления».
5. **Поиск.** Запрос словами раскладывается на условия, и отели делятся на три группы: «подходит», «возможно, данных не хватает» и «не подходит». У каждого отеля есть объяснение.
6. **Отельер.** Когда данных нет или уверенность низкая, система ставит вопрос в очередь. Вопросы отбираются по пользе, не больше 3 на отель. Отельер отвечает свободным текстом в кабинете, ответ раскладывается по полям и становится фактом с источником «отельер». Мгновенного ответа агент не обещает. Отельера мы имитируем: три ответа заранее внесены в демо-базу.
7. **Новая характеристика по описанию словами.** LLM пишет рецепт из существующих инструментов. Код проверяет рецепт пробным прогоном на 5 отелях и отбраковывает вырожденный результат, до 3 попыток. Затем характеристика считается для всех отелей.
8. **Как пользоваться.** Всё это доступно как MCP-сервер, то есть набор инструментов для любого AI-ассистента, и как веб-интерфейс. Вкладки: поиск с картой, карточка отеля с источниками, сравнение, кабинет отельера, характеристики, метрики, журнал.

## Что нового

Состояние на 27.10.2026, сборка с вердиктом в карточке. Числа взяты с живого приложения (`/api/status`, `/api/metrics`, `/api/truth/audit`) и из замера `bench/results/integration.json` против `baseline.json`.

1. **Какой номер брать.** Для каждой категории номера считаем вероятность вида на море, говорим, какую сторону и с какого этажа просить, и пишем готовую просьбу для брони. Разобрано 1843 категории, у 519 из них (в 73 отелях) карточка вида не обещает, а расчёт его видит. Совпадение с отзывами гостей именно этой категории: 11 из 11, но выборка маленькая.
2. **Вид из окна.** Симулятор по стороне, этажу и месяцу, с панорамой и закатом. Проверен на 55 отелях: картинка согласована с оценкой моря в каждом. Один расчёт занимает около 0,1 с.
3. **Ночь по часам.** График шума по сторонам здания с 20:00 до 09:00, с окном открытым и закрытым. Совпал с базой шума в 40 проверенных отелях из 40. Порог для сна 30 дБ в комнате, это норма ВОЗ.
4. **Движок правды.** Если источники спорят, считается апостериор, а не побеждает самый громкий. Где сильные отзывы гостей спорят с расчётом, мы теперь верим гостям: 26 из 26 таких отелей (раньше в этих 26 побеждал расчёт); одиночное заявление отельера физику не переворачивает (120 из 120 синтетических заявлений против расчёта, по 40 на вид, тишину и закат; раньше отельер побеждал почти всегда: в среднем физика держалась в 28% случаев). Ошибка калибровки уверенности 0,172 против 0,068, но почти весь выигрыш даёт Wi-Fi, на остальных характеристиках калибровка не улучшилась.
5. **Проверка обещаний.** Сверяем карточку с расчётом: 45 подтверждено, 107 скрытая сильная сторона, 12 спорно, 0 завышено (завышенное говорим только при надёжных входах, иначе «спорно»).
6. **Черновики.** Характеристика, собранная агентом, не видна публике, пока админ не одобрит. К каждому черновику идёт авто-отчёт: покрытие, однородность, согласие с независимым сигналом. Проверено на сборке без LLM: черновик закрыт для публики и открывается после одобрения.
7. **Проверенные ответы чата.** После ответа без LLM сверяются цифры и названия отелей с выводами инструментов. На 5 подсунутых выдуманных ответах поймано 5, ложной тревоги на верном ответе нет. Качественные фразы («тихий район») эта проверка не видит.
8. **Фото как датчик.** 873 кадра в 222 отелях размечены зрением модели. Где на фото из номера видно море, расчёт тоже его видит в 20 из 20 случаев. Отрицательный итог («моря на фото нет») фактом не становится: отели снимают лучшие номера.
9. **Что, если ослабить условия.** Если строгий запрос ничего не находит или находит мало, показываем, какое условие дороже всего и сколько отелей откроет его снятие. На трёх строгих запросах раньше ослаблений было 0, теперь есть у всех трёх.
10. **Радар изменений.** Всплески жалоб, падение оценки, стройки рядом и истёкшие факты. На реальных данных 24 сигнала на 229 отелей (около 10%), искусственный всплеск ловится.
11. **Новый регион одной командой.** Адлер, 339 отелей, собран тем же конвейером. Около 2 минут расчёта плюс загрузка OSM, у нас она заняла 25 минут из-за перегруженных серверов. Рамку региона и источник шума «аэропорт» пришлось добавить руками.

Ещё: поиск без LLM честно называет потребности, которых нет в реестре, и вердикт наверху карточки отеля. Он показывает, какой номер брать и что попросить, а если движку номеров просить нечего, так и пишет.

## Как тестировали

- **Прогон.** Скрипт `scripts/usecases.py` отправляет 12 запросов от лица гостя в чат-агента. Агент сам выбирает инструменты через наш MCP-сервер. Прогон идёт на копии базы, поэтому демо-данные не портятся.
- **Что проверял.** Я (Claude) читал каждый ответ на три вещи: нет ли выдуманных фактов, правильно ли названы источники и уверенность, и чего не хватило системе.
- **Повторный прогон.** Найденные пробелы закрыты кодом, затем прогон повторён полностью. В таблице ниже результаты второго прогона.

## Что здесь правда, а что нет

- **Ответы агента настоящие.** Таблица выше: дословная выжимка того, что он ответил. Его рассуждения и выбор инструментов никто не подкручивал.
- **Цифры взяты из базы, агент их не выдумал.** Для проверки я сверил выборочно цитату «50 м от пляжа» у Серенити, температуру моря 18,3 / 17,0 / 15,8 °C по декадам ноября, железную дорогу в 71 м от Cosmos и ответы отельеров. Всё совпало с базой и сырыми данными.
- **Но цифры это расчёт, а не замер.** Децибелы, «море видно с N-го этажа» и минуты до пляжа: это модель по открытым картам. Для «вида на море» точность проверена на 46 отелях независимой разметкой модели, не человека (`docs/accuracy.md`): полнота 0,47, ложные «видно» не измерить; для остальных характеристик проверки против реальности нет. Метрики выше это совпадение с карточкой и отзывами, тоже неточными источниками.
- **Ответов отельеров всего три, и все придуманы нами** (`scripts/seed_demo.py`): Грейс Горизонт (собаки до 10 кг), Cosmos (стеклопакеты), Просперус (вид с 3–9 этажа). ТЗ разрешает имитировать отельера, но на демо говорить об этом прямо.
- **Агент местами ошибается в формулировках:** «15 из 16» вместо «15 из 15 пользовавшихся», «расчёт не учитывает деревья» (учитывает), уверенность 1.0 у вида на море (завышена).

## Что нашли тестами и уже исправили

- **Закат и тишина считались отдельно.** Отель мог пройти, хотя окна на закат выходят на шумную сторону. Добавлены «закат с тихой стороны» и «море с тихой стороны». На флагманский запрос теперь подходят 19 отелей вместо 33.
- **Новые характеристики**, которых просил агент:
  - «Без лестниц»: лифт по карточке, этажность по OSM, ступеньки на входе через вопрос отельеру;
  - «Интернет для работы»: оценка Wi-Fi гостями из отзывов, раньше мы её выбрасывали при подготовке данных;
  - «Заселение ночью»: круглосуточный ресепшен;
  - «Где поесть рядом»;
  - «Тишина днём»;
  - «Море по декадам месяца».
- **Агент вызывал инструменты с выдуманными параметрами.** Теперь в описании инструмента перечислены допустимые параметры, а при ошибке агент получает подсказку и исправляется сам.
- **Фильтр по тегам OSM молча ничего не находил**, когда агент передавал список значений. Исправлено.
- **Подозрительные маршруты получали полную уверенность.** Если путь по дорожкам в 3 раза длиннее прямой, уверенность теперь снижена.

## Известные проблемы

Две главные проблемы прошлой версии отчёта закрыты:

- **Отельер против расчёта.** На физике (вид, шум, закат) одиночное заявление отельера больше не переворачивает расчёт: 120 из 120 синтетических заявлений против расчёта не прошли (это свойство движка, а не проверка правоты расчёта). На политике отеля (питомцы, заселение) отельер по-прежнему главный, это задумано.
- **Одобрение новых характеристик.** Характеристика от агента сначала черновик, публика её не видит, пока админ не одобрит.

Что остаётся:

1. **Уверенность «тихой ночи» принимает всего два значения.** Для `night_quiet` резолвер почти не различает отели по уверенности, поэтому её нельзя показывать как тонкую шкалу.
2. **Пороги слова «тихо» не сведены.** В поиске «тихо» значит ниже 50 дБ снаружи, в графике ночи ниже 55 дБ снаружи, для сна 30 дБ в комнате. Каждый порог объяснён в интерфейсе, но единого нет.
3. **Черновики не проверены в режиме LLM.** Сборку характеристик словами и авто-отчёт проверили без LLM. Живую LLM-сборку и отчёт по её результату перед сдачей нужно прогнать вручную.
4. **Определения «скрытого вида» разные** (см. таблицу выше). Это три честных, но разных числа, и на демо нужно называть, какое из них показываем.
5. **Прежние ошибки агента в формулировках** (сценарии 8, 9, 12: «деревья не учитываются», «дневной шум не считал», путь до аквапарка по прямой ×1,3) исправлялись правкой карточки возможностей и проверкой ответов, но на новой сборке сценарии не перепрогоняли.
6. **Скорость сборки характеристики** 6–10 минут. На демо лучше показывать заранее собранную характеристику.
7. **LLM в Docker.** В контейнере нет Claude Code, поэтому LLM там работает только по API-ключу. Ветку с ключом Anthropic вживую не проверяли. Проверены OpenAI-совместимый ключ и подписка Claude.
8. **Карта и числа это расчёт, а не замер.** Децибелы, этаж с видом и минуты до пляжа посчитаны по открытым картам; для вида на море есть разметка модели на 46 отелях (`docs/accuracy.md`), человеческой разметки нет.

## Как запустить самим

```bash
git clone git@github.com:hackathon-ostrovok-felicita-2026/ostrovok-agent.git
cd ostrovok-agent
cp .env.example .env        # ключ LLM по желанию, без него работают правила
docker compose up           # веб: http://localhost:8000, MCP: http://localhost:8001
```

Без Docker: `uv venv -p 3.12 && . .venv/bin/activate && uv pip install -r requirements.txt && make run`. Сценарии, которые стоит попробовать в первую очередь, есть в README в разделе «Что попробовать». Например, отель «Просперус» с готовыми ответами отельера.
